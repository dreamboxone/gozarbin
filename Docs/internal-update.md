# به‌روزرسانی داخلی گذربین

در سربرگ مستقل «به‌روزرسانی» گذربین، «بررسی نسخهٔ جدید» نسخهٔ پایدار GitHub را بررسی می‌کند.
اگر بستهٔ سازگار با معماری روتر، خانوادهٔ نسخهٔ OpenWrt و مدیر بسته وجود داشته
باشد، دکمهٔ «دانلود و به‌روزرسانی تفاضلی» فعال می‌شود. هسته و رابط LuCI با هم دریافت
می‌شوند؛ Psiphon از نسخهٔ 2.3.0 داخل بستهٔ اصلی قرار دارد. تنظیمات را مدیر بسته حفظ می‌کند.

نسخهٔ نصب‌شده و آخرین نسخهٔ GitHub نمایش داده می‌شوند؛ پس از اتمام نصب، نسخهٔ
نهایی از فایل نسخهٔ نصب‌شده خوانده و با نسخهٔ مقصد تطبیق داده می‌شود.
درصد دانلود از بایت‌های دریافتی، شامل درخواست Range در حال انجام، محاسبه می‌شود.
درصد نصب با تکمیل مراحل نصب گذربین، نصب LuCI، بررسی نسخه و راه‌اندازی سرویس
افزایش پیدا می‌کند؛ این عدد درصد پیشرفت مراحل است، نه تخمین بایت‌های نوشته‌شده روی فلش.

```sh
gozarbinctl update check
gozarbinctl update status
gozarbinctl update install
```

عملیات در پس‌زمینه اجرا می‌شود. وضعیت در `/var/run/gozarbin-update/state.json`
و خروجی تشخیصی در `/var/run/gozarbin-update/log` قرار می‌گیرد.
دریافت و کنترل همهٔ بسته‌ها پیش از نصب انجام می‌شود؛ نصب با `opkg` یا `apk`
است و تراکنش بازگشت خودکار برای چند بسته فراهم نمی‌کند.

بایگانی مشترک گذربین و LuCI همراه فهرست قطعه‌هایش در `/etc/gozarbin/update-cache` نگه‌داری
می‌شود. در به‌روزرسانی بعدی، قطعه‌های مشترک از این بایگانی خوانده می‌شوند و فقط
بخش‌های متفاوت با HTTP Range دریافت می‌شوند. SHA-256 نتیجه باید دقیقاً با بستهٔ
منتشرشده یکی باشد. اگر کش وجود نداشته باشد، اشتراک کافی نباشد یا درخواست Range
ناموفق شود، دریافت کامل انجام می‌شود. کش خراب نیز هیچ‌گاه نصب نمی‌شود.
فقط یک نسل کش بایگانی نگه‌داری می‌شود و در فضای کم، ذخیرهٔ کش انجام نمی‌شود.
برای آزادکردن فضا می‌توان این پوشه را پاک کرد؛ به‌روزرسانی بعدی کامل خواهد بود.

گردش‌کار انتشار برای هر معماری و نسخهٔ OpenWrt یک فایل
`gozarbin-openwrt-<release>-<arch>.tar.gz` منتشر می‌کند که هر دو بستهٔ گذربین و
LuCI مرتبط داخل آن هستند. فایل‌های APK/IPK به‌صورت جداگانه منتشر نمی‌شوند؛
فقط فایل‌های checksum و `.chunks.json` کنار بایگانی قرار می‌گیرند.
فشرده‌سازی بسته‌ها و بایگانی با مرزهای
پایدار انجام می‌شود تا تغییر کوچک تمام دادهٔ فشرده را تغییر ندهد؛ قالب قابل نصب
APK/IPK حفظ می‌شود. بایگانی‌ها و manifestها در `SHA256SUMS.txt` درج می‌شوند.
این checksumها از همان انتشار HTTPS دریافت می‌شوند و امضای مستقل انتشار نیستند.

اولین انتشار دارای این دارایی‌ها باید در GitHub منتشر شود تا این قابلیت روی روتر
قابل استفاده باشد. نسخه‌های قدیمی که دارایی‌های تفاضلی ندارند از این مسیر نصب
نمی‌شوند. برچسب‌های `vX.Y.Z` و `vX.Y.ZrN` پشتیبانی می‌شوند؛ برای نمونه
`v5.7.29r2` در OpenWrt به نسخهٔ بستهٔ `5.7.29-r2` تبدیل می‌شود.

آزمون‌ها:

```sh
python3 test/test-update.py
python3 test/test-assets.py
python3 test/test-delta.py  # نیازمند ucode و ماژول fs
```

اگر پس از نصب رابط، خطای `Permission denied` دیده شد، یک بار از LuCI خارج شوید
و دوباره وارد شوید. برای بازخوانی مجوزهای نشست‌های موجود، در SSH روتر اجرا کنید:

```sh
/etc/init.d/rpcd reload
```

نسخهٔ `5.7.29r2` پس از نصب، این بازخوانی را با تأخیر کوتاه انجام می‌دهد تا درخواست
نصب قطع نشود. اصلاح قالب بایگانی و مجوزها پس از انتشار اولیهٔ `5.7.29` انجام شده؛
نسخهٔ اولیهٔ آن برای ورود به قالب جدید به نصب دستی بستهٔ مشترک نیاز دارد.
